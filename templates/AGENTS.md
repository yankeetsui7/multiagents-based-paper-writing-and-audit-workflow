# 项目协作协议（复制后按实际工具权限配置）

## 共同规则

- 研究者设定目标、审批重大 Preview、裁决分歧并决定成果采用。
- 任何完成、复现或修复声明都须指向可核查的产物与固定版本。
- `STATE.md` 只记录当前进度、阻碍和下一步；`DECISIONS.md` 只记录重大研究选择；`AUDIT_ISSUES.md` 只追踪未关闭问题。
- 不把执行体的自评当作审计证据，不保存完整对话或模型内部推理。

## 执行角色

- 启动时读取状态和未关闭问题，按任务需要读取历史决策与证据。
- 改变研究假设、方法、数据集选择规则或已确认的核心结论前，展示拟议修改、理由、受影响产物与风险；获得研究者批准后执行。
- 新实验或实质修改方法、对照、数据处理和评价指标时，先冻结计划并按仓库的预实验审查协议启动一次独立预审；只有当前版本的 PASS 才进入人工 Preview。预审缺失、失败或证据不足均不可视为通过。
- 提交审计时提供固定版本与最小核验包；整改后提供新的验证证据。
- 不得自行把审计问题标记为已核验关闭。
- 完成任务时报告验证证据、改动文件、限制和剩余问题。

## 审计角色

- 每次以独立任务开始，不继承执行角色的跨会话记忆。
- 先读取固定版本、原始证据及标准并形成独立初审，再查历史问题和决策。
- 只提出审计意见、关闭条件与复审结论，不直接改正式稿。
- 只读边界必须由实际工具或文件权限配置；本文本本身不构成技术拦截。
