# 论文 AI 协作链

一套面向长期论文项目的最小工作流：一个持续执行的 Agent、一个无跨会话记忆的独立审计 Agent，以及由研究者裁决的项目状态。它是可复制的流程模板，不包含具体研究资料。

## 技术路线

1. **版本化工作区**：论文、数据说明、分析脚本和结果各有固定版本标识。大型数据可另存，但必须在证据索引中记录可追溯的版本或校验值。
2. **精简持久状态**：`STATE.md` 记录当前进度，`DECISIONS.md` 记录重大选择及理由，`EVIDENCE.md` 建立主张与原始材料的对应关系，`AUDIT_ISSUES.md` 跟踪未关闭问题。原始证据和历史记录按需读取，不把全部对话当作事实库。
3. **角色隔离**：执行 Agent 负责研究、实验、分析、写作和整改；审计 Agent 独立核查，不继承执行 Agent 的主观总结，也不能直接改写正式论文或已确认决策。研究者负责研究方向、争议裁决和采用决定。
4. **两级审计**：每周中段审计检查增量、遗留问题和累积一致性；终段审计检查完整论文、证据链与可复现性。
5. **最小核验包**：每次审计以固定版本和明确证据为输入。具体边界见 [BOUNDARIES.md](BOUNDARIES.md)。

## 一轮工作流

```text
研究者设定目标与验收标准
  → 执行 Agent 产出研究增量与证据
  → 重大修改预览（理由、依据、影响范围）
  → 冻结待审版本并提交最小核验包
  → 审计 Agent 独立初审
  → 审计 Agent 对照历史决策与旧问题复核
  → 研究者裁决分歧；执行 Agent 整改
  → 审计 Agent 验证整改并关闭问题
  → 更新状态、重大决策和下一步
```

中段审计按周运行；终段审计在拟采用完整成果时运行，并可在重大整改后复审。终审结论为 `Accepted`、`Revision Required` 或 `Rejected`。`Accepted` 仅表示通过本项目的内部标准，不代表期刊录用。

## 从模板开始

复制 `templates/` 到自己的**私有研究工作区**，填写项目目标与验收标准。每轮审计复制 `HANDOFF.md` 模板，填入当前版本和证据路径。公开仓库只维护流程与空白模板；研究数据、未发表论文、审计细节和个人信息留在私有工作区。

## 设计来源

本流程根据用户提供的《逆向解析协作系统》对话记录提炼。记录讨论了文件式项目状态、执行与审计角色隔离、每周中段审计、终段审计、决策理由记忆及最小交接包。此仓库是对这些想法的流程化整理，未声称经过实证评估。
